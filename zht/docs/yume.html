開篇：宇浩輸入平臺是什麼 ​

宇浩輸入平臺（Yume）是宇浩自研的原生輸入法程序：一個 Rust 內核加上各平臺的原生 界面，不依賴 Rime，也不依賴任何第三方輸入法。下載即用，不需要部署，不需要編輯配置 文件。

它與《各平臺下載和安裝》所講的 Rime 掛載方案並列，而非取代。 想要 Rime 的生態與可配置性，走那條路；想要開箱即用、設置全在菜單裏，走這條路。碼表、 拆分、字集三者兩邊同源。

靈明、星陳、卿雲、日月、拼音五個方案內置，隨時切換；也可以上傳自己的碼表，當場編成 一個可用方案。

一句話點題：確定帶來自由。每個漢字基本對應唯一編碼，打字不必停下來挑字。

一、安裝 ​

1.1 選哪個版本 ​

版本是否需要安裝適合
Windows 便攜版解壓即用絕大多數人；公司電腦、無管理員權限、U 盤
Windows 安裝版（TSF）需管理員，一次性想要內嵌輸入欄、想讓系統把它當正式鍵盤
macOS 版拖進文件夾Mac 用户

拿不定主意就用便攜版。兩者功能已經齊平，差別只有內嵌輸入欄一項（見 3.8）。

1.2 Windows 便攜版：解壓即用 ​

  1. 下載 Yume-Portable-*.zip，把整個 Yume 文件夾解壓到可寫的位置（桌面、文檔、 U 盤皆可）。
  2. 雙擊 YumePortable.exe。
  3. 任務欄右下角出現紫色「宇」圖標即已就緒，直接在任何輸入框打字。
  4. 右鍵該圖標即是全部設置。

不要解壓到 C:\Program Files

便攜版要在自己的文件夾裏寫設置和詞庫，那個位置沒有寫權限。直接在壓縮包的預覽窗口裏 運行同理。程序會當場報錯，而不是默默把你的設置丟掉。

1.3 Windows 安裝版（TSF） ​

  1. 下載 Yume-Setup-*.exe 並運行。SmartScreen 會攔一次，點「更多信息 ▸ 仍要運行」 ——安裝包沒有做代碼簽名。
  2. 設置 ▸ 時間和語言 ▸ 語言和區域 ▸ 中文 ▸ 語言選項 ▸ 鍵盤 ▸ 添加鍵盤 ▸ 宇浩。
  3. Win+空格 切到宇浩。托盤圖標爲藍色。

1.4 macOS ​

  1. 把 Yume.app 拖進 ~/Library/Input Methods/。
  2. 註銷重新登入一次。只有首次安裝需要，以後更新不必。
  3. 系統設置 ▸ 鍵盤 ▸ 輸入法 ▸ ＋ ▸ 中文 ▸ 靈明 ▸ 添加。

⌃空格 切換。設置菜單在系統菜單欄的輸入法圖標下。

1.5 更新與卸載 ​

  • 便攜版：托盤菜單「檢查本輸入法更新包」只做提示並打開下載頁——它蓋不掉正在運行 的自己。下了新包後把 Resources\ 和 exe 覆蓋舊的即可。UserData\ 不在壓縮包內， 設置和詞庫不會丟。 卸載就是删掉文件夾。
  • 安裝版：托盤菜單「檢查本輸入法更新包」直接下載並安裝。卸載走「應用和功能」。
  • macOS：菜單裏檢查更新，自動下載安裝。

1.6 其他平臺 ​

網頁版 https://yume.shurufa.app 免安裝，可以先試手感，功能是桌面版的子集。

Linux（fcitx5）內核已經就緒，界面尚未實作。

二、開始輸入 ​

2.1 先認清你的方案屬於哪一類 ​

宇浩四個形碼方案分兩家，分界是一個字的編碼怎麼結束。兩家的打字節奏不同，後面 3.3 的上屏模式和 6.1 的手動切分還要各用一次這條分界，所以放在最前。

星陳・卿雲靈明・日月
類型限長方案自定碼方案（前綴碼）
最大碼長4靈明 4、日月 5
一個字怎麼結束打滿最大碼長，或按空格末碼是韻碼，編碼自報結束
編碼分割不唯一，需分隔唯一
手感近於五筆、鄭碼——

需要辨析一句：兩類方案都是限長的，自定碼方案只是在限長之外額外具備自定屬性。 這裏是按「靠什麼結束」分家。術語見《瓊林擷英》的 限長與前綴碼。

拼音方案不在此表——它只走整句模式，見 3.3。

2.2 限長方案：星陳、卿雲 ​

  • 全碼四碼。打滿四碼自動上屏，不必再按空格。
  • 不滿四碼的簡碼，按空格上屏。這裏的空格既是分隔符，也可以看作簡碼的最後一碼。

以星陳打「不用等候」：

字編碼碼長怎麼上屏
不v一級簡碼按空格
用sy二級簡碼按空格
等gh二級簡碼按空格
候eubj全碼滿四碼，自動上屏

整串按鍵是 v␣sy␣gh␣eubj。

2.3 自定碼方案：靈明、日月 ​

  • 字根的末碼落在 a e i o u 五個韻碼上。韻碼與輔音兩區互斥，所以編碼自己 知道自己在哪裏結束——連續敲下去就行，中途不需要空格。
  • 例子：eioua → 的是我不了。五個字一氣呵成，中間一次停頓也沒有。
  • 韻碼之外，打滿最大碼長同樣自動上屏（靈明 4、日月 5）。

這就是首頁所説的「確定帶來自由」。

2.4 候選、選重與翻頁 ​

分家到此爲止，以下各節兩類方案通用。

鍵作用
1–9選第 1–9 個候選
;選第 2 個候選
'選第 3 個候選
← →上／下一頁（豎排佈局）
↑ ↓上／下一頁（橫排佈局）

宇浩重碼極低，多數字一次到位，選重鍵平時用不上。

2.5 空格與回車 ​

  • 空格：有候選則上屏高亮候選；有編碼但沒有候選（半段碼）則原樣上屏編碼；沒有 編碼則打出一個空格。
  • 回車：緩衝非空時，一律把編碼原樣上屏。打英文單詞時很順手。
  • 退格：逐碼删。Esc：清空。

2.6 中英與標點 ​

  • 單擊 Shift 切中／英。
  • 組字中打大寫字母直接進臨時英數模式，打完按空格上屏。
  • 空緩衝時首鍵是數字或 + -，進臨時數字模式，123.45% 之類原樣輸出，不轉全角。
  • 中文模式下英文標點自動轉全角中文標點，引號自動開合。有編碼時先上屏首選再出標點。

2.7 用 z 反查拼音、叫回歷史 ​

空緩衝按 z 進拼音反查，可以整句解碼，註釋欄會告訴你這個字的形碼編碼。z 也可以叫 回最近上屏過的內容。

三、常用設置 ​

3.1 三條路通同一個開關 ​

入口怎麼用適合
設置面板Ctrl+Shift+O，或托盤菜單「設置」第一次設置、看全貌
斜線命令空緩衝打 /，再打命令名，如 /mode打字中途、手不離鍵盤
快捷鍵Ctrl+Shift+ 某鍵高頻切換

三條路改的是同一個值，改完立刻生效，沒有確認按鈕。

3.2 方案 ​

內置五個方案：靈明、星陳、卿雲、日月四個宇浩系列形碼，加一個拼音 （全拼，可切雙拼）。

  • Ctrl+Shift+N 在形碼方案間循環，/schema。
  • Ctrl+Shift+I 進出拼音，/pinyin。

各方案的字根與規則見《靈明》《星陳》 《日月》等既有頁面，本文不重複。

3.3 上屏模式：三選一 ​

這一節決定打字手感，值得看清楚。

模式行爲適合
頂字上屏模式〔默認〕延遲一字，下一字的編碼把前一字「頂」上屏絕大多數人
自動上屏模式編碼一旦唯一確定即上屏追求無停頓、盲打
整句輸入模式連打一串，由語言模型切分成句，一次上屏長句、詞語多、拼音方案

各版本的出廠默認都是頂字上屏，所以列在第一行。Ctrl+Shift+M 循環，/mode。

整句模式下，兩類方案的行爲不同

這是 2.1 那條分界線的第二次現身。

限長方案（星陳、卿雲）在整句模式下只認全碼，簡碼不進整句，一碼字也不參與。原因 是沒有韻碼作邊界，簡碼只是全碼的前綴，整句無從判斷它到哪裏結束。

自定碼方案（靈明、日月）沒有這個限制，簡碼照用。

星陳、卿雲用户若想在整句裏用簡碼，辦法見 6.1 的手動切分。

3.4 字集：過濾與排序 ​

兩個獨立的開關，不要混爲一談：過濾是不顯示，排序是顯示但後置。

  • 過濾：全部漢字／僅常用漢字／僅簡化漢字／僅傳統漢字／僅自定義字集。 Ctrl+Shift+0 循環，/charset。
  • 排序：原始排序／常用字優先／簡化字優先／傳統字優先／自定義字集優先。沒有快捷鍵， 走菜單。

建議：只打現代簡體，過濾選「僅簡化漢字」；打古籍，過濾選「全部」加排序「傳統字優先」。

3.5 單字派 ​

三檔：字詞同出（默認）／主單副詞／嚴格單字。Ctrl+Shift+D，/word。

「主單副詞」下具體顯示哪幾類詞語，另有五個勾選，見 4.5。

3.6 注解 ​

三檔：關閉／二重（拆分、分節碼）／多重（再加讀音、字義、字集、Unicode 碼位）。

Ctrl+Shift+/ 循環，/comment；組字中單按 / 也可以循環（拼音方案除外）。

學習期建議開多重。

3.7 候選面板外觀 ​

這幾項都是設一次就不動的。

  • 候選佈局：傳統豎排／簡約橫排／極簡內嵌。Ctrl+Shift+L，/layout。 極簡內嵌僅安裝版與 macOS 有。
  • 每頁候選數 3–9：Ctrl+Shift+3 到 Ctrl+Shift+9。
  • 序號欄、註釋欄、註腳欄的顯隱：/index、/head、/foot。
  • 半角／全角標點：Ctrl+Shift+.，/punc。
  • 預測候選（僅差韻碼即成字的提示）：Ctrl+Shift+Y。
  • 空格簡碼、變體漢字的顯隱：Ctrl+Shift+K、/variation。
  • 空空如也（完全隱藏候選面板）：Ctrl+Shift+H。

3.8 內嵌輸入欄 ​

本節僅適用於 Windows 安裝版與 macOS

便攜版靠全局鍵盤鈎子工作，宿主程序裏沒有可供繪製的預編輯區，所以沒有「內嵌輸入欄」 「內嵌時預覽首選」「極簡內嵌佈局」三項。這是設計取捨，不是缺陷；便攜版其餘功能與安 裝版齊平。

內嵌輸入欄把編碼直接畫在光標處，而不是浮動面板上。「內嵌時預覽首選」再進一步，把首 選漢字而不是編碼畫在那裏。兩項都走菜單（/preedit、/preview），沒有快捷鍵。

3.9 還原默認 ​

菜單「還原默認設置」，或 /default。

四、進階功能 ​

4.1 快捷字符（; 引導） ​

空緩衝按 ; 打開 26 鍵對照面板，再按一個字母就上屏一段文本——標點、符號、漢字或整 段話都可以。面板另有 ; , . $ 四個固定條目。

菜單「編輯快捷字符表」自定義。26 條全部留空即關閉此功能。

4.2 符號與 Unicode ​

  • / 引導符號命令：/tab 插一個制表符、/version 打出版本號等。
  • // 後接十六進制碼位，直接輸出該 Unicode 字符。

宇浩系列另有 fh jm py bd dy yj kk 等編碼引導符，與 Rime 方案相同，見 《各平臺下載和安裝》，此處不重複。

4.3 三個浮動面板 ​

都在候選高亮時按。

鍵面板用途
Tab查閱面板單字查字統網，詞語查漢典
⇧Tab相似部件九宮格按拆分字根的子序列檢索同部件字，學習利器
←→ 或 ↑↓更多候選格狀面板一屏鋪開全部候選

4.4 用户詞庫 ​

菜單「編輯用户詞庫」，或 Ctrl+Shift+U、/user。

表格式編輯：「字詞」列填內容，「用户編碼」列可以留空（自動編碼），也可以填多個（空格 分隔）。

每個方案各有一份，自定義方案也一樣。用户詞庫中的詞語不受單字派限制，一律顯示。

4.5 更多詞語功能設置 ​

承接 3.5。主單副詞模式下，勾選要顯示哪幾類詞語：兩字／三字／四字／四字以上／白名單。 出廠五項全關，即開箱只出單字，要哪類自己勾。

靈明方案另有「使用傳統構詞法」一項，其他方案看不到。

4.6 自定義字集 ​

菜單「編輯自定義字集」。可以勾七個現成字集（通用規範漢字、調和傳統漢字、香港常用字、 常用與次常用國字、古籍通用規範漢字等）和 Unicode 區塊，再加白名單、黑名單。

面板自帶「測試」框：把字符粘進去，逐字告訴你會不會顯示、是哪一條勾選在起作用。

定好之後配合 3.4 的「僅自定義字集」使用。

4.7 拼音與雙拼 ​

Ctrl+Shift+I 進出拼音方案。

雙拼有七種預設：自然碼、微軟、搜狗、紫光、拼音加加、智能 ABC、國標。另有自定義 佈局編輯器，可以配出任意方案。

z 反查與拼音方案共用同一套佈局設置。

4.8 幾個順手的小功能 ​

  • 注解上屏 Ctrl+Shift+A：把高亮候選的注解（拆分、讀音、碼位等）當文本上屏。寫 教程、發羣消息時很方便。
  • 截圖候選面板 Ctrl+Shift+J：把當前候選面板 2× 重繪後複製到剪貼板。查閱面板打 開時按 Ctrl+Shift+Alt+J，只截本地那一半，不含在線字典。
  • 暫停／恢復輸入法 Ctrl+Space：所有按鍵直通程序，托盤圖標轉灰。打遊戲、用快捷 鍵密集的軟件時用。
  • 登入時自動啓動（僅便攜版）：托盤菜單勾選，只寫一個註册表值，取消即淨。

4.9 便攜版引擎（安裝版用户） ​

安裝版托盤菜單有「使用便攜版引擎」一項，把打字交給便攜版助手——用於文字服務驅動不了 的程序。

開啓時會提示你把系統鍵盤佈局切到英文，否則系統選中的另一個輸入法仍會疊加自己的中英 狀態和候選窗。高權限窗口下該開關會被拒絕並説明原因。

4.10 模態編輯器（helix、vim） ​

模態編輯器的 normal 模式裏，h j k l w b 是命令不是字。輸入法不知道這回 事，照樣把它們收進編碼區，於是每進出一次 normal 模式就要手動切一次中英。

Yume 提供一條命令，讓編輯器在換模式時自己把輸入法支開、再叫回來：

平臺掛起恢復
Windowsyume-mode offyume-mode on
macOSYumeIME --suspendYumeIME --resume

Windows 安裝版會把安裝目錄加進 PATH，所以直接寫 yume-mode 即可。macOS 的可執行文 件在 /Library/Input Methods/Yume.app/Contents/MacOS/YumeIME，配置裏寫全路徑，或自 己在 /usr/local/bin 建個軟鏈接。

掛起是整個讓開，不是切英文模式：Yume 自己的快捷鍵（單擊 Shift 切中英、 Ctrl+Shift+ 那一排、Ctrl+Space）在掛起期間一併交還編輯器。它也不動中英狀態 ——掛起前是英文模式，恢復後仍是英文模式。

helix ​

寫進 config.toml（Windows 在 %AppData%\helix\，macOS 在 ~/.config/helix/）：

toml
[keys.normal]
i = [":sh yume-mode on", "insert_mode"]
a = [":sh yume-mode on", "append_mode"]
I = [":sh yume-mode on", "insert_at_line_start"]

幾點説明 ​

  • 編輯器崩了不會把鍵盤鎖住。 焦點離開該窗口時掛起自動解除。代價是從别的窗口切回 一個停在 normal 模式的編輯器時，輸入法是醒着的，可能吃掉第一下按鍵。
  • 管理員身份運行的終端無效：系統不允許普通權限的程序向高權限窗口發消息。
  • helix 進入插入模式的路子不止上面七條（gi 等），漏綁一條的後果只是那一次要手動切， 不會出錯。

五、自定義方案：用自己的碼表 ​

5.1 能做到什麼 ​

上傳一份碼表文件，Yume 當場編譯成一個可用方案：最大碼長、自分割字母、字根編碼、取碼 規則全部由碼表反推（Zhu Bootstrapping Algorithm），不需要你寫任何配置。

編好之後與內置方案同等待遇——有自己的用户詞庫，能用注解，能切換。

5.2 碼表格式 ​

每行 漢字 <Tab> 編碼，或者 編碼 <空格> 漢字，UTF-8 編碼。文件名第一個點 之前就是方案名。

5.3 三步走 ​

  1. 上傳。 方案管理面板裏選碼表文件。
  2. 確認參數。 帶「⚠」的幾項是碼表自己也説不清的，最該過目。
  3. 編譯完成。 報告最大碼長、自分割字母、碼表條目數、還原率。

5.4 給得越多，推得越準 ​

你提供的系統還要推的拆分注解質量
只有碼表拆分 ＋ 字根編碼 ＋ 取碼規則反推，還原率約八成
碼表 ＋ 拆分表字根編碼 ＋ 取碼規則拆分完全以你的表爲準
碼表 ＋ 拆分表 ＋ 字根表只剩取碼規則編碼一個字母都不會被推翻
  • 拆分表：每行 漢字 <Tab> 拆分序列。宇浩自家的 chaifen.txt 可以直接用。
  • 字根表：每行 字根 <Tab> 編碼。字根寫法必須與拆分表一致——一邊寫「氵」一邊 寫「水」就對不上。

5.5 方案管理 ​

命名、重新上傳、配置、撤銷（只能退一步）、删除、從方案列表隱藏、注解中隱藏拆分或編碼， 都在方案管理面板裏。槽位有上限。

六、細節與疑難 ​

6.1 整句模式：用 ` 手動切分 ​

這是 2.1 那條分界線的第三次現身。整句模式下引擎要自己把一串字母切成段：**自定碼方案 （靈明、日月）**的切分由韻碼決定，引擎不必猜；限長方案（星陳、卿雲）沒有韻碼，字母 是真歧義，引擎只能猜。

按反引號 `（數字 1 左邊那個鍵）就能親手畫一道段界，把猜測變成事實。它與 Rime 方案的精確造詞是同一個鍵、同一個意思。

它做兩件事：

  1. 這個字到此爲止——沒有任何單字候選能跨過這道界。
  2. 界前那一段是完整的，因此 3.3 提到的「限長方案整句只認全碼」就此解除，簡碼重新 可用。例如卿雲的 um`qf`jtp 用三個簡碼打出「庆丰收」。

` 不是韻碼，它不進碼表、不參與查詢，所以它能對所有方案通用，而永遠不會與方案自 己的字母打架。連按兩次等同一次。

6.2 打錯了，整段編碼留在原地 ​

現象：輸入非法或死路編碼時，整段原樣留在編碼區，不被切碎。

原因：Yume 不做空碼回退。

怎麼辦：退格改。這是刻意設計——寧可讓你自己改，也不把一段編碼切成不合法的分段。

6.3 候選面板被開始菜單擋住 ​

現象：在開始菜單、任務欄搜索框裏打字，面板看不見。

原因：那些界面畫在比普通窗口更高的層級上。

怎麼辦：不必做什麼。兩個 Windows 版都已改爲讓位——把面板挪到旁邊而不是疊上去， 輸入正常。徹底蓋過去需要簽名的高權限進程，屬於未來工作。

6.4 便攜版與安裝版同時運行 ​

現象：每個按鍵被處理兩次，中英狀態各自翻轉、對不齊。

原因：兩者都掛了鍵盤鈎子。

怎麼辦：只留一個。便攜版啓動時偵測到安裝版會主動詢問。

托盤圖標紫色是便攜版、藍色是安裝版、灰色是已暫停，一眼就知道是誰在打字。

6.5 便攜版的文件放在哪 ​

  • Resources\ 唯讀，隨更新覆蓋。
  • UserData\ 是你的設置和詞庫，不在壓縮包內，更新不會碰它。

托盤菜單「打開用户文件夾」直達。U 盤拔插後只要相對位置不變就能用。

6.6 高權限窗口下打不了字 ​

現象：在以管理員身份運行的程序裏，便攜版沒有反應。

原因：Windows 的權限隔離不讓普通權限的鈎子看到高權限窗口的按鍵。

怎麼辦：改用安裝版。

6.7 剛更新完，某個程序還是舊行爲 ​

僅安裝版會這樣。

原因：Windows 把輸入法 DLL 常駐在每一個用過它的進程裏。

怎麼辦：重開那個程序。

6.8 出了問題怎麼反饋 ​

  • 診斷日誌 yume.log：便攜版在 UserData\ 下，安裝版和 macOS 在用户數據文件夾下 （菜單「打開用户文件夾」直達）。
  • GitHub Issues
  • QQ 交流羣
