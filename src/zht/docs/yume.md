## 開篇：宇浩輸入平臺是什麼

〔注：三四段，不寫成技術説明。要點——〕

- 宇浩輸入平臺（Yume）是宇浩自研的**原生輸入法程序**：一個 Rust 內核 ＋ 各平臺原生界面，不依賴 Rime、不依賴任何第三方輸入法。下載即用，不需要部署、不需要編輯配置文件。
- 它與《[各平臺下載和安裝](/zht/docs/install)》所講的 **Rime 掛載方案並列，而非取代**。想要 Rime 的生態與可配置性，走那條路；想要開箱即用、設置全在菜單裏，走這條路。碼表、拆分、字集三者兩邊同源。
- 靈明、星陳、卿雲、日月、拼音五個方案內置，隨時切換；亦可上傳自己的碼表編成方案。
- 一句話點題：**確定帶來自由**——每個漢字基本對應唯一編碼，打字不必停下來挑字。〔注：此處刻意不提「無需空格」，那是自定碼方案一家的特性，見 2.1。〕

## 一、安裝

### 1.1 選哪個版本

〔注：一張三行小表，讀者掃一眼就能決定。列：免安裝／需管理員／內嵌輸入欄／適合誰。〕

| 版本                      | 是否需要安裝     | 適合                                     |
| ------------------------- | ---------------- | ---------------------------------------- |
| **Windows 便攜版**        | 解壓即用         | 絕大多數人；公司電腦、無管理員權限、U 盤 |
| **Windows 安裝版（TSF）** | 需管理員，一次性 | 想要內嵌輸入欄、想讓系統把它當正式鍵盤   |
| **macOS 版**              | 拖進文件夾       | Mac 用户                                 |

〔注：明確寫一句「拿不定主意就用便攜版」，並説明兩者功能已齊平，差別只有內嵌輸入欄一項。〕

### 1.2 下載

〔注：三個渠道並列，各給一句適用説明。〕

- [GitHub 發佈頁](https://github.com/forfudan/yume-release/releases)——版本最全、最新

### 1.3 Windows 便攜版：解壓即用

〔注：編號步驟，不超過五步。要點——〕

1. 下載 `Yume-Portable-*.zip`，**整個 `Yume` 文件夾**解壓到可寫的位置（桌面、文檔、U 盤皆可）。
2. 雙擊 `YumePortable.exe`。
3. 任務欄右下角出現**紫色「宇」圖標**即已就緒；直接在任何輸入框打字。
4. 右鍵該圖標＝全部設置。

::: warning 不要解壓到 `C:\Program Files`
〔注：解釋——便攜版要在自己的文件夾裏寫設置與詞庫，該處無寫權限；直接在壓縮包預覽窗口裏運行同理。程序會當場報錯而非默默丟失設置。〕
:::

## 二、開始輸入

〔注：本章是全文最該短的一章。目標——讀完就能打字。〕

### 2.1 先認清你的方案屬於哪一類

〔注：本章的樞紐。宇浩四個形碼方案分兩家，分界是「一個字的編碼怎麼結束」；節奏不同，後面 3.3 上屏模式與 6.1 手動切分還要各用一次，故放在最前。〕

|                    | 星陳・卿雲               | 靈明・日月                   |
| ------------------ | ------------------------ | ---------------------------- |
| 類型               | 限長方案                 | 自定碼方案（前綴碼）         |
| 最大碼長           | 4                        | 靈明 4、日月 5               |
| **一個字怎麼結束** | 打滿最大碼長，或按空格   | 末碼是韻碼，編碼自報結束     |
| 編碼分割           | 不唯一，需分隔           | 唯一                         |
| 手感近於           | 五筆、鄭碼               | ——                           |

〔注：表下附一句辨析，免得與《瓊林擷英》打架——**兩類方案都是限長的**，自定碼方案只是在限長之外**額外**具備自定屬性；這裏按「靠什麼結束」分家。術語見《瓊林擷英》的[限長](/zht/docs/concepts#限長)與[前綴碼](/zht/docs/concepts#前綴碼)。〕

〔注：再一句——拼音方案不在此表，它只走整句模式，見 3.3。〕

### 2.2 限長方案：星陳、卿雲

〔注：要點——〕

- 全碼四碼。**打滿四碼自動上屏**，不必再按空格。
- 不滿四碼的簡碼，**按空格上屏**。此處的空格既是分隔符，也可視作簡碼的最後一碼。
- 例子：以星陳打「不用等候」四字——

  | 字  | 編碼   | 碼長     | 怎麼上屏         |
  | --- | ------ | -------- | ---------------- |
  | 不  | `v`    | 一級簡碼 | 按空格           |
  | 用  | `sy`   | 二級簡碼 | 按空格           |
  | 等  | `gh`   | 二級簡碼 | 按空格           |
  | 候  | `eubj` | 全碼     | 滿四碼，自動上屏 |

  〔注：已對照 Yume 隨包碼表 `data/xing.txt` 覈實，四字皆傳承字，陸標簡碼與繁簡通打兩表通用。定稿時把整串實際按鍵寫出來：`v␣sy␣gh␣eubj`。〕

<!-- 截圖：星陳打「不用等候」，候選面板 + 空格上屏 -->

### 2.3 自定碼方案：靈明、日月

〔注：要點——〕

- 字根的末碼落在 `a e i o u` 五個韻碼上。韻碼與輔音兩區互斥，所以**編碼自己知道自己在哪結束**——連續敲下去即可，中途無需空格。
- 例子：`eioua` → 的是我不了。五個字一氣呵成，中間一次停頓也沒有。
- 韻碼之外，打滿最大碼長同樣自動上屏（靈明 4、日月 5）。
- 一句話收束：這就是首頁所説的「確定帶來自由」。

### 2.4 以下各節，兩類方案通用

〔注：這是一行過渡句，不是小節標題，定稿時併入 2.5 開頭。作用是告訴讀者分家到此爲止。〕

### 2.5 候選、選重與翻頁

〔注：小表。〕

| 鍵      | 作用                   |
| ------- | ---------------------- |
| `1`–`9` | 選第 1–9 個候選        |
| `;`     | 選第 2 個候選          |
| `'`     | 選第 3 個候選          |
| `←` `→` | 上／下一頁（豎排佈局） |
| `↑` `↓` | 上／下一頁（橫排佈局） |

〔注：附一句——宇浩重碼極低，多數字一次到位，選重鍵平時用不上。〕

### 2.6 空格與回車

〔注：兩條規則，寫清楚差別，這是新手最易困惑處。〕

- **空格**：有候選 → 上屏高亮候選；有編碼但無候選（半段碼）→ **原樣上屏編碼**；無編碼 → 打出一個空格。
- **回車**：緩衝非空時，一律把編碼**原樣上屏**（打英文單詞時很順手）。
- **退格**：逐碼删。**Esc**：清空。

### 2.7 中英與標點

〔注：要點——〕

- **單擊 Shift** 切中／英。
- 組字中打**大寫字母**直接進臨時英數，打完空格上屏。
- 空緩衝時首鍵爲數字或 `+` `-` 進**臨時數字模式**，`123.45%` 之類原樣輸出，不轉全角。
- 中文模式下英文標點自動轉全角中文標點，引號自動開合。有編碼時先上屏首選再出標點。

### 2.8 用 `z` 反查拼音、叫回歷史

〔注：兩句。空緩衝按 `z` 進拼音反查，可整句解碼；`z` 亦可叫回最近上屏過的內容。〕

### 3.2 方案

〔注：五個內置方案一句話各一。靈明／星陳／卿雲／日月爲宇浩系列形碼，拼音爲全拼（可切雙拼）。切換：`Ctrl+Shift+N` 在形碼間循環，`Ctrl+Shift+I` 進出拼音。各方案的字根與規則指向 /zht/docs/ling 等既有頁面，本文不重複。〕

### 3.3 上屏模式：三選一

〔注：本節是全文最值得寫清楚的一節，因爲它決定打字手感。三種模式各給「怎麼動」「適合誰」。〕

| 模式                     | 行爲                                     | 適合                     |
| ------------------------ | ---------------------------------------- | ------------------------ |
| **頂字上屏模式**〔默認〕 | 延遲一字，下一字的編碼把前一字「頂」上屏 | 絕大多數人，各版本出廠值 |
| **自動上屏模式**         | 編碼一旦唯一確定即上屏                   | 追求無停頓、盲打         |
| **整句輸入模式**         | 連打一串，由語言模型切分成句，一次上屏   | 長句、詞語多、拼音方案   |

〔注：**頂字上屏爲各版本出廠默認**，故列在第一行；正文要明説這一點，讀者才知道自己現在處於哪一檔。`Ctrl+Shift+M` 循環，`/mode`。〕

::: warning 整句模式下，兩類方案的行爲不同
〔注：承 2.1，這是那條分界線的第二次現身，必須寫。要點——**限長方案（星陳、卿雲）在整句模式下只認全碼**，簡碼不進整句；一碼字亦不參與。原因是沒有韻碼作邊界，簡碼只是全碼的前綴，整句無從判斷它到哪結束（引擎的 `fluency_full_code_only`）。**自定碼方案（靈明、日月）沒有這個限制**，簡碼照用。星陳、卿雲用户若想在整句裏用簡碼，辦法是 6.1 的手動切分。〕
:::

### 3.4 字集：過濾與排序

〔注：兩個獨立的開關，各四檔，別混爲一談。過濾＝不顯示；排序＝顯示但後置。〕

- 過濾：全部漢字／僅常用漢字／僅簡化漢字／僅傳統漢字／僅自定義字集。`Ctrl+Shift+0` 循環。
- 排序：原始排序／常用字優先／簡化字優先／傳統字優先／自定義字集優先。無快捷鍵，走菜單。
- 一句話給建議：只打現代簡體 → 過濾「僅簡化漢字」；打古籍 → 過濾「全部」＋排序「傳統字優先」。

### 3.5 單字派

〔注：三檔。字詞同出（默認）／主單副詞／嚴格單字。`Ctrl+Shift+D`。「主單副詞」下具體顯示哪類詞語另有五個勾選，指向 4.5 節，此處不展開。〕

### 3.6 注解

〔注：三檔：關閉／二重（拆分・分節碼）／多重（＋讀音・字義・字集・Unicode 碼位）。`Ctrl+Shift+/`；組字中單按 `/` 亦可循環（拼音方案除外）。學習期建議開多重。〕

## 四、進階功能

### 4.1 快捷字符（`;` 引導）

〔注：空緩衝按 `;` 打開 26 鍵對照面板，再按字母即上屏一段文本——標點、符號、漢字或整段話皆可。面板另有 `;` `,` `.` `$` 四個固定條目。菜單「編輯快捷字符表」自定義；26 條全空即關閉此功能。〕

### 4.2 符號與 Unicode

〔注：`/` 引導符號命令（`/tab` 插制表符、`/version` 打版本號等）；`//` 後接十六進制碼位直接輸出該 Unicode 字符。宇浩系列另有 `fh` `jm` `py` `bd` `dy` `yj` `kk` 等編碼引導符，同 Rime 方案，鏈接到 install.md 對應段落，不重複列。〕

### 4.8 幾個順手的小功能

〔注：短列表，各一句。〕

- **注解上屏** `Ctrl+Shift+A`：把高亮候選的注解（拆分、讀音、碼位等）當文本上屏。寫教程、發羣消息時很方便。
- **截圖候選面板** `Ctrl+Shift+J`：把當前候選面板 2× 重繪後複製到剪貼板。
- **暫停／恢復輸入法** `Ctrl+Space`：所有按鍵直通程序，托盤圖標轉灰。打遊戲、用快捷鍵密集的軟件時用。
- **登入時自動啓動**（僅便攜版）：托盤菜單勾選，只寫一個註册表值，取消即淨。

## 五、自定義方案：用自己的碼表

〔注：本章面向方案作者與折騰派。可寫得稍長，但仍分步。〕

### 5.1 能做到什麼

〔注：一段。上傳一份碼表文件，Yume 當場編譯成一個可用方案：最大碼長、自分割字母、字根編碼、取碼規則全部由碼表**反推**（Zhu Bootstrapping Algorithm），不需要你寫任何配置。編好之後與內置方案同等待遇——有自己的用户詞庫、能用注解、能切換。〕

### 5.2 碼表格式

〔注：每行 `漢字<Tab>編碼` 或 `編碼<空格>漢字`，UTF-8。文件名第一個點之前即方案名。〕

〔注：**寫正文時務必記得**——`<Tab>` 這類尖括號一旦裸露在 Markdown 裏，VitePress 會當成 Vue 組件而編譯失敗，全篇凡出現處一律包進反引號。〕

### 5.3 三步走

〔注：編號步驟。上傳 → 確認參數（帶「⚠」的幾項是碼表自己也説不清、最該過目的）→ 編譯完成，報告最大碼長、自分割字母、碼表條目數、還原率。〕

<!-- 截圖：方案管理面板 -->
<!-- 截圖：參數確認窗口，「⚠」項高亮 -->

### 5.4 給得越多，推得越準

〔注：這是本章的關鍵一節，用一張遞進表講清楚。〕

| 你提供的                 | 系統還要推的                 | 拆分注解質量             |
| ------------------------ | ---------------------------- | ------------------------ |
| 只有碼表                 | 拆分 ＋ 字根編碼 ＋ 取碼規則 | 反推，還原率約八成       |
| 碼表 ＋ 拆分表           | 字根編碼 ＋ 取碼規則         | 拆分完全以你的表爲準     |
| 碼表 ＋ 拆分表 ＋ 字根表 | 只剩取碼規則                 | 編碼一個字母都不會被推翻 |

〔注：附兩條格式説明——拆分表每行 `漢字<Tab>拆分序列`，宇浩自家 `chaifen.txt` 可直接用；字根表每行 `字根<Tab>編碼`，字根寫法須與拆分表一致（一邊「氵」一邊「水」就對不上）。〕

### 5.5 方案管理

〔注：命名、重新上傳、配置、撤銷（只能退一步）、删除、從方案列表隱藏、注解中隱藏拆分／編碼。槽位有上限。〕

## 六、細節與疑難

〔注：本章收全部「需要留神」的點。體例統一：**現象 → 原因 → 怎麼辦**，每條不超過一段。〕

### 6.1 整句模式：用 `` ` `` 手動切分

〔注：本節值得寫足，是全文最技術的一處，也是老用户最需要的。要點——〕

- 承 2.1 那條分界線的第三次現身。整句模式下引擎要自己把一串字母切成段：**自定碼方案（靈明、日月）**的切分由韻碼決定，引擎不必猜；**限長方案（星陳、卿雲）沒有韻碼，字母是真歧義，引擎只能猜**。
- 按**反引號 `` ` ``**（數字 1 左邊那個鍵）即可親手畫一道段界，把猜測變成事實。與 Rime 方案的「[精確造詞](/zht/docs/install#精確造詞)」是同一個鍵、同一個意思。
- 它做兩件事：①**這個字到此爲止**——沒有任何單字候選能跨過這道界；②**界前那一段是完整的**，因此 3.3 提到的「限長方案整句只認全碼」就此解除，簡碼重新可用。舉例：卿雲的 ``um`qf`jtp`` 三個簡碼打出「庆丰收」。
- 補一句原理註腳：`` ` `` 不是韻碼，它不進碼表、不參與查詢，所以它能對所有方案通用而永不與方案自己的字母打架。
- 註：連按兩次等同一次（幂等）。
- 〔注：本節寫足，但要在 3.3 的提示框裏留一句「辦法見 6.1」的指路，讓星陳、卿雲用户不至於漏掉。〕

### 6.2 打錯了，整段編碼留在原地

〔注：現象——輸入非法／死路編碼時，整段原樣留在編碼區不被切碎。原因——**不做空碼回退**，寧可讓你退格改，也不把它切成不合法的分段。這是刻意設計。〕

### 6.3 候選面板被開始菜單擋住

〔注：現象——在開始菜單、任務欄搜索框裏打字，面板看不見。原因——那些界面畫在比普通窗口更高的層級。現狀——兩個 Windows 版都已改爲**讓位**（把面板挪開而非疊上去），能正常輸入；徹底蓋過去需要簽名的高權限進程，屬未來工作。〕

### 6.4 便攜版與安裝版同時運行

〔注：現象——每個按鍵被處理兩次，中英狀態各自翻轉、對不齊。原因——兩者都掛鍵盤鈎子。辦法——只留一個；便攜版啓動時偵測到安裝版會主動詢問。附一句：托盤圖標**紫色＝便攜版、藍色＝安裝版、灰色＝已暫停**，一眼就知道是誰在打字。〕

### 6.5 便攜版的文件放在哪

〔注：`Resources\` 唯讀、隨更新覆蓋；`UserData\` 是你的設置與詞庫，不在壓縮包內、更新不會被碰。托盤菜單「打開用户資料夾」直達。USB 拔插後只要相對位置不變即可用。〕

### 6.6 高權限窗口下打不了字

〔注：現象——在以管理員身份運行的程序裏，便攜版無反應。原因——Windows 的權限隔離不讓普通權限的鈎子看到高權限窗口的按鍵。辦法——改用安裝版。〕

### 6.7 剛更新完，某個程序還是舊行爲

〔注：僅安裝版。原因——Windows 把輸入法 DLL 常駐在每個用過它的進程裏。辦法——重開那個程序即可。〕
